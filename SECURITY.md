# Security Policy

## Reporting a Vulnerability

Security is important to Zwernemann_Withdrawl.

If you believe you have found a security vulnerability, please do **not** report it through a public GitHub issue.

Instead, please contact the maintainer privately and provide as much information as possible to help reproduce and investigate the issue.

Please include:

* A description of the vulnerability
* The affected version of Zwernemann_Withdrawl
* The affected Magento 2 version, if relevant
* Steps to reproduce the issue
* The potential impact
* Any suggested mitigation, if available

Please do not include passwords, API keys, access tokens, customer data, order information or other confidential or personal information in your report.

## What Happens Next

We will review the report and assess its severity and potential impact.

If the vulnerability is confirmed, we will work on a fix and, where appropriate, release an updated version of the module.

We will keep the reporter informed during the investigation where possible.

Once a fix is available, the vulnerability may be disclosed publicly together with the relevant release information. The timing and details of any disclosure will depend on the severity of the issue and the availability of a fix.

## Supported Versions

Security fixes are generally provided for the latest released version of Zwernemann_Withdrawl.

| Version        | Supported |
| -------------- | --------- |
| Latest release | Yes       |
| Older releases | Limited   |

Users are encouraged to keep Zwernemann_Withdrawl and Magento 2 up to date.

## Scope

Security reports may include issues affecting:

* Authentication and authorization
* Customer and order data
* Cart and checkout operations
* Administrative functionality
* API endpoints
* Data handling and storage
* External API integrations
* Prompt and AI related security issues
* Injection or manipulation of AI tool calls
* Exposure of API credentials or other secrets

Please note that vulnerabilities in third party services such as Magento, Anthropic, Voyage AI or Pinecone should normally be reported to the respective provider.

## Responsible Disclosure

We appreciate responsible disclosure and ask security researchers to give us a reasonable opportunity to investigate and fix a vulnerability before making it public.

Thank you for helping keep Zwernemann_Withdrawl secure.
